¿Qué pasa dentro de un componente?

// src/App.tsx (simplificado)

export default function App() {

  const { state, view, dispatch } =

    useExpressionEvaluator(); // el puente

  return (

    <aside>

      <TraversalsBlock

        traversals={state.traversals} />

      <StackVisualizer stack={view.stack} />

      <ResultBlock step={view.currentStep}

        history={view.history} />

    </aside>

  );

}

Componente = función

Recibe datos (props) y regresa lo que se dibuja.

// src/components/ResultBlock.tsx

function ResultBlock({ step, history, finished }) {

  // 1. recibe datos ya calculados (props)

  const operaciones = history.filter(

    (s) => s.kind === 'APPLY_OPERATOR');

  // 2. regresa lo que se dibuja (JSX)

  return (

    <Section label="D" title="Resultado">

      <p>{formatNumber(step.result)}</p>

      {operaciones.map((op) => (

        <li>{op.izquierdo} {op.info} {op.derecho}

          = {op.result}</li>

      ))}

    </Section>

  );

}

Para terminar con el código, veamos qué hay dentro de un componente de la pantalla. En React, un componente es una función. Recibe datos y regresa lo que se tiene que dibujar. A los datos que recibe se les llama props, que viene de propiedades, y se escriben como si fueran atributos de una etiqueta HTML. A la izquierda está App, simplificado. En la primera línea llama al hook, el puente, y recibe tres cosas: state, que es el estado guardado, como el árbol y los recorridos; view, que son datos ya preparados para dibujar, como el contenido de la pila en el paso actual; y dispatch, que es la forma de mandar avisos. Después regresa la pantalla: el bloque de recorridos recibe los recorridos, el bloque de la pila recibe la pila, y el bloque de resultado recibe el paso actual y el historial de pasos. App solo reparte los datos; no calcula nada. A la derecha está por dentro el bloque D, el de Resultado. Recibe el paso actual, el historial y si ya terminó. Lo primero que hace es filtrar el historial para quedarse solo con los pasos donde se aplicó un operador; esos son los resultados parciales. Después regresa lo que se dibuja: una sección con el título Resultado, el número final y una lista con cada operación, por ejemplo 18 − 6 = 12. Fíjense en algo importante: este componente nunca suma ni divide. El 12 ya venía calculado dentro del paso, porque lo calculó el evaluador. El componente solo decide cómo se ve. Todos los bloques de la pantalla funcionan así: el árbol, la pila, el Modo Tutor. Por eso, si hubiera un error en el resultado, sé que tengo que buscarlo en la lógica y no en la pantalla.
