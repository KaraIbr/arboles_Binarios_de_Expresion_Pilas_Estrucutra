La salida de una pieza es la entrada de otra

// src/core/ExpressionTree.ts

static fromExpression(source: string) {

  // 1. texto → piezas

  const tokens = new Lexer(source).tokenize();

  // 2. piezas → árbol (regresa la raíz)

  const root = new Parser(tokens).parse();

  return new ExpressionTree(source, tokens, root);

}

// 3. árbol → lista de nodos en posorden

posorden() {

  return posorden(this.root);

}

ExpressionTree une las piezas

texto → Lexer → piezas → Parser → raíz → posorden

// src/core/evaluator.ts (simplificado)

function evaluatePostorder(tree) {

  const pila = new Stack<StackEntry>();

  for (const nodo of tree.posorden()) {

    if (typeof nodo.info === 'number') {

      pila.push({ key: nodo.id, value: nodo.info })

      continue;

    }

    const derecho = pila.pop().value; // 1er POP

    const izquierdo = pila.pop().value; // 2do POP

    const valor =

      applyOperator(izquierdo, nodo.info, derecho);

    pila.push({ key: nodo.id, value: valor });

  }

  return pila.top(); // TOPE = resultado

}

Aquí se ve cómo se pasan los datos de una pieza a otra, ya con el código real del proyecto. A la izquierda está ExpressionTree, que es el que organiza la cadena. Su función fromExpression recibe el texto. En la primera línea crea un Lexer con ese texto y le pide tokenize, que regresa la lista de piezas. En la segunda línea le entrega esas piezas a un Parser y le pide parse, que regresa la raíz del árbol. Con eso ya tengo el árbol completo, y lo guardo junto con el texto original y las piezas. Fíjense que el Lexer no sabe que existe un Parser, y el Parser no sabe de dónde salieron las piezas: solo reciben y entregan. Abajo está posorden, que simplemente llama a la función recursiva de los recorridos empezando por la raíz. A la derecha está el corazón del proyecto: la evaluación. Crea una pila vacía y recorre la lista que le dio el posorden. Si el nodo es un número, hace PUSH y pasa al siguiente. Si es un operador, hace los dos POP, en este orden: primero el derecho y después el izquierdo. Luego llama a applyOperator, que es la función que hace la suma, resta, multiplicación o división, y también la que revisa la división entre cero. El resultado se mete a la pila con PUSH. Al final, el valor que queda en el tope es el resultado. Esta versión está simplificada para que quepa. La real hace lo mismo, pero además guarda una fotografía de cada paso: cómo estaba la pila antes y después, y una frase que explica lo que pasó. Esa lista de fotografías es la que usa la pantalla para avanzar paso a paso y la que narra el Modo Tutor. Y como es la misma pila que expliqué antes, aquí se ve que las piezas se reutilizan: el evaluador no programa su propia pila, usa la clase Stack.
