Recorridos y pila reutilizada

// src/core/traversals.ts

function posorden(nodo, visita = []) {

  if (nodo === null) return visita; // NIL

  posorden(nodo.izq, visita); // IZQ

  posorden(nodo.der, visita); // DER

  visita.push(nodo); // Visitar

  return visita;

}

// preorden: visita.push(nodo) va primero

// inorden: visita.push(nodo) va en medio

Igual al algoritmo 6.4 de Cairo

Solo cambia dónde va «Visitar». null es NIL.

// src/core/notations.ts (reutiliza Stack)

function evaluatePrefix(preorden) {

  const pila = new Stack<number>();

  for (let i = preorden.length - 1; i >= 0; i--) {

    const nodo = preorden[i];

    if (typeof nodo.info === 'number') {

      pila.push(nodo.info);

    } else {

      const izquierdo = pila.pop(); // 1er POP

      const derecho = pila.pop();

      pila.push(applyOperator(izquierdo,

        nodo.info, derecho));

    }

  }

  return pila.pop();

}

Aquí están los recorridos en código, y se ve que son casi idénticos a los algoritmos de Cairo. La función posorden recibe un nodo y una lista donde va anotando las visitas. La primera línea es el caso base: si el nodo es null, que es nuestro NIL, regresa sin hacer nada. Si no, se llama a sí misma con el hijo izquierdo, luego con el derecho, y hasta el final agrega el nodo a la lista; ese es el «Visitar». Para el preorden y el inorden la función es la misma, solo cambia de lugar la línea que agrega el nodo: en el preorden va antes de las dos llamadas y en el inorden va en medio. A la derecha está la evaluación del preorden, la que da el valor tenue que aparece junto a la notación prefija. La pongo aquí para mostrar cómo se comparten las piezas: no programé una pila nueva ni otra forma de sumar o dividir. Uso la misma clase Stack y la misma función applyOperator que usa el evaluador principal. Lo que cambia es la dirección y el orden de los POP. El ciclo va del último nodo al primero, por eso empieza en preorden.length menos 1 y va bajando. Los números entran con PUSH. Cuando llega un operador, el primer POP es el izquierdo y el segundo el derecho, justo al revés que en el posorden, porque ahora estoy leyendo al revés. Si aquí usara el orden del posorden, la resta y la división darían el signo o el resultado equivocados. Con esto se ve la ventaja de tener las piezas separadas: agregar una nueva forma de evaluar me costó unas cuantas líneas, porque todo lo demás ya existía y ya estaba probado.
