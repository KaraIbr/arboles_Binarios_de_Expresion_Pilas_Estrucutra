El nodo: IZQ, INFO y DER

Como en Cairo, cada nodo es un registro de tres campos. En las hojas, IZQ y DER valen NIL (en el programa, null). Árbol de (5+3)*2:

NodoIZQINFODER
×→ nodo +×→ nodo 2
+→ nodo 5+→ nodo 3
5NIL5NIL
3NIL3NIL
2NIL2NIL

// Cairo: NODO = REGISTRO IZQ, INFO, DER

// src/core/Node.ts

class TreeNode {

  readonly izq: TreeNode | null; // IZQ (null = NIL)

  readonly info: NodeInfo; // INFO: número u operador

  readonly der: TreeNode | null; // DER (null = NIL)

}

 

// Así queda (5+3)*2 en memoria:

const cinco = new TreeNode('n0', 5); // NIL, NIL

const tres = new TreeNode('n1', 3);

const suma = new TreeNode('n2', '+', cinco, tres);

const dos = new TreeNode('n3', 2);

const raiz = new TreeNode('n4', '*', suma, dos);

Grado

Hojas (números): 0 hijos. Operadores: siempre 2 hijos.

Direcciones

IZQ y DER guardan la dirección de otro nodo, no posiciones seguidas.

Ya sabemos cómo se ve el árbol; ahora veamos cómo se guarda en la memoria. Usé exactamente la representación de Cairo: cada nodo es un registro con tres campos. IZQ guarda dónde está el hijo izquierdo, INFO guarda el dato y DER guarda dónde está el hijo derecho. La tabla muestra cómo queda (5 + 3) × 2. La raíz es la multiplicación: en INFO tiene el por, en IZQ apunta al nodo de la suma y en DER apunta al nodo del 2. La suma, a su vez, apunta al 5 y al 3. Y los números, como son hojas, tienen IZQ y DER en NIL: no apuntan a nada. En el código es la clase TreeNode, con los mismos tres campos: izq, info y der. Lo que Cairo llama NIL, en JavaScript se escribe null. Abajo del código se ve el orden en que se crea este árbol: primero las hojas, 5 y 3; luego la suma, que ya puede apuntar a ellas; luego el 2; y al final la raíz. Se construye de abajo hacia arriba, porque un nodo solo puede apuntar a hijos que ya existen. Eso es justo lo que hace el analizador sintáctico cada vez que crea un nodo. Hay dos detalles que conviene notar. El primero es el grado: las hojas siempre tienen cero hijos y los operadores siempre tienen dos. El segundo es que IZQ y DER guardan direcciones, no posiciones seguidas. Cada nodo está donde el sistema le encontró espacio, y lo que los une son esos enlaces, igual que en las listas ligadas. Y algo que no hay que olvidar: el lado sí importa. Si en una resta intercambiara IZQ y DER, el resultado cambiaría de signo.
