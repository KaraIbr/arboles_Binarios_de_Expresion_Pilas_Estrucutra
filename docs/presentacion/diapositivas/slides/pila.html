// src/core/Stack.ts (simplificado)

// lista enlazada con apuntador al TOPE

push(value) {

  // la celda nueva apunta al tope anterior

  this.topCell = { value, next: this.topCell };

}

pop() {

  if (this.topCell === null) throw ERROR;

  const cell = this.topCell;

  this.topCell = cell.next; // baja el tope

  return cell.value;

}

peek() { /* TOPE: lo lee sin sacarlo */ }

Para calcular necesito la segunda estructura del proyecto: la pila. A diferencia del árbol, la pila es lineal, y su regla es muy simple: el último que entra es el primero que sale. Es como una pila de platos: solo puedo poner o quitar el de arriba. Tiene cuatro operaciones. PUSH pone un elemento arriba. POP saca el de arriba. TOPE solo mira el de arriba, sin sacarlo. Y Vacía pregunta si ya no queda nada. En la tabla se ve un ejemplo: meto el 18, meto el 6, miro el tope y es el 6, lo saco, y queda el 18. En el código hice la pila como una lista ligada, con un apuntador que siempre señala al tope, parecido a los enlaces IZQ y DER del árbol. Cuando hago PUSH, creo una celda nueva que apunta a la que antes estaba arriba, y ahora el tope es la nueva. Cuando hago POP, guardo el valor de arriba y muevo el apuntador a la celda de abajo. No tengo que recorrer nada, así que no importa si hay dos elementos o mil: las dos operaciones tardan lo mismo. Las pilas están en muchos lugares: el Ctrl+Z, que deshace primero lo último que hiciste; el botón Atrás del navegador; y la propia recursión, que guarda sus llamadas pendientes en una pila, como acabamos de ver. ¿Y qué pasa si intento sacar algo de una pila vacía? No hay nada que sacar. En mi programa eso solo podría pasar si la expresión estuviera mal armada, y en lugar de inventar un valor, la pila lo detecta y avisa con un error controlado.
